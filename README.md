# Suaru

**Демо:** ____________ — публичная ссылка на Render (вставить после деплоя, см. «Деплой на Render»).

Веб-приложение для фермеров: ставите точку на карте, выбираете культуру и технику —
получаете оценку, сколько воды нужно полю на ближайшие дни, сколько сгорит дизеля
и сколько CO₂ при этом выделится.

Проект сделан на хакатоне AuaHack (трек «Экология», Казахстан).

## Что показывает

По точке на карте и данным поля:

- **вода** — сколько миллиметров и кубометров нужно полить за выбранное число дней;
- **по дням** — дата, дождь и сколько полить в этот день;
- **дизель** — сколько литров топлива уйдёт на обработку поля;
- **CO₂** — сколько килограммов углекислого газа выделится при сжигании этого дизеля.

Все числа считаются на сервере по формулам ниже. Это **оценка**: модель упрощённая,
без учёта типа почвы, стадии роста растений и потерь при поливе.

## Формулы

- Потребность в воде за день, мм: `max(0, ET0 × Kc − осадки)`,
  значения ET0 и осадков берутся из Open-Meteo.
- Суммарная вода, мм: сумма дневной потребности за выбранные дни.
- Объём воды: `м³ = мм × 10 × площадь_га` (1 мм на 1 га = 10 м³).
- Дизель: `л = площадь_га × (расход_л_ч / скорость_га_ч)` — один проход техники.
- CO₂: `кг = литры × 2.65`.

Источники коэффициентов:

- `Kc` — FAO-56 «Crop evapotranspiration» (Allen et al., 1998), Table 12.
  В `calc.py` проверены mid-season значения: пшеница 1.15, ячмень 1.15,
  кукуруза 1.20, картофель 1.15, рис 1.20.
  https://www.fao.org/4/x0490e/x0490e0b.htm
- `CO2_PER_L = 2.65` кг CO₂/л — расчёт из IPCC 2006 Guidelines, Vol. 2, Ch. 2,
  Table 2.2: 74.1 кг CO₂/ТДж; теплота сгорания 43.0 ТДж/Гг; плотность 0.832 кг/л.
  `74.1 × 43.0 / 1000 × 0.832 = 2.65`.
  https://www.ipcc-nggip.iges.or.jp/public/2006gl/pdf/2_Volume2/V2_2_Ch2_Stationary_Combustion.pdf

## Запуск локально

```bash
python -m venv venv
venv\Scripts\activate        # Windows (PyCharm: выберите этот интерпретатор)
source venv/bin/activate     # macOS / Linux
pip install -r requirements.txt
uvicorn main:app --reload
```

Открыть:

- приложение — http://127.0.0.1:8000/
- документация API — http://127.0.0.1:8000/docs

Проверить формулы:

```bash
python test_calc.py
```

## API

`POST /api/plan`

```json
{
  "lat": 43.24,
  "lon": 76.89,
  "crop": "wheat",
  "area_ha": 10,
  "l_per_h": 12,
  "ha_per_h": 2,
  "days": 3
}
```

Пример ответа (погода меняется, цифры будут другими):

```json
{
  "mm": 4.83,
  "m3": 483.0,
  "diesel_l": 60.0,
  "co2_kg": 159.0,
  "kc": 1.15,
  "daily": [
    { "date": "2026-10-24", "et0_mm": 1.6, "rain_mm": 0.0, "need_mm": 1.84, "need_m3": 184.0 },
    { "date": "2026-10-25", "et0_mm": 1.35, "rain_mm": 0.0, "need_mm": 1.55, "need_m3": 155.25 },
    { "date": "2026-10-26", "et0_mm": 1.25, "rain_mm": 0.0, "need_mm": 1.44, "need_m3": 143.75 }
  ]
}
```

Ошибки: `400` — неверные данные (текст на русском), `502` — Open-Meteo не ответил
или вернул неполные данные.

`GET /api/health` → `{"status": "ok"}` — health check для Render и прогрева
ссылки перед демо.

Эндпоинт `POST /api/plan/batch` и стадии роста добавляются ветками
backend/frontend: контракт меняется только аддитивно — старые поля не
переименовываются и не удаляются, клиент игнорирует незнакомые поля.

## Демо на 60 секунд

1. **Пин на карте** (15 сек): открыть ссылку, одним кликом поставить точку
   там, где поле. «Один клик — и вот координаты поля».
2. **Расчёт** (15 сек): проверить форму (культура, площадь, техника) и нажать
   «Рассчитать». Показать итог: вода в мм и м³.
3. **Календарь по дням** (20 сек): разобрать построчный список — где дождь,
   где полив. «Если завтра дождь, полив уменьшается — мы не поливаем под дождь».
4. **/docs** (10 сек): открыть `/docs` — «API открыто и документировано,
   проверяйте любым curl».

## Деплой на Render

Деплой описан в [render.yaml](render.yaml) (Blueprint):

1. Смержить три ветки (backend, frontend, docs) в `main`: до мержа
   backend-ветки не существует `/api/health`, и Render не примет деплой
   (health check отвечает 404).
2. Запушить `main` на GitHub.
3. Render → New → Blueprint → подключить репозиторий — сервис создаётся
   по `render.yaml`: Python 3.12, сборка `pip install -r requirements.txt`,
   запуск `uvicorn main:app --host 0.0.0.0 --port $PORT`,
   health check `/api/health`.
4. Вставить публичную ссылку в строку «Демо» в начале README.

Если Blueprint не используется — тот же результат вручную:

1. Render → New → Web Service → подключить репозиторий.
2. Build command: `pip install -r requirements.txt`
3. Start command: `uvicorn main:app --host 0.0.0.0 --port $PORT`
4. Health check path: `/api/health`

FastAPI сам раздаёт `static/`, поэтому нужен один сервис.
Free-план засыпает после простоя — ссылку надо прогреть заранее
(последний пункт чеклиста).

## Чеклист после деплоя

- [ ] Ссылка открывается на телефоне: панель, форма и карточка не обрезаются.
- [ ] `GET /api/health` отвечает `200` и `{"status": "ok"}`.
- [ ] `/docs` открывается, «Try it out» работает.
- [ ] Два одинаковых запроса подряд: второй отвечает мгновенно —
      погода берётся из кэша (10 минут).
- [ ] Ошибка без интернета: выключить Wi-Fi, нажать «Рассчитать» — понятное
      русское сообщение; включить Wi-Fi, нажать ещё раз — работает.
- [ ] Прогрев за 5 минут до защиты: открыть ссылку и `/api/health`,
      чтобы free-план разбудился.

## Ручные проверки в браузере (для команды)

Облачный агент Chromium не запускает — эти проверки делает человек
на машине с браузером:

1. **Консоль**: DevTools → Console — без красных ошибок после загрузки,
   клика по карте и расчёта; Network → `POST /api/plan` — 200, числа в ответе
   совпадают с карточкой на экране.
2. **Мобильный вид**: DevTools → responsive 375×667 — панель, форма и
   карточка не обрезаются, кнопка «Рассчитать» достижима большим пальцем.
3. **Карта**: тайлы OpenStreetMap загрузились (не серые), пин ставится одним
   тапом, зум работает, подпись «© OpenStreetMap» видна.
4. **Перезагрузка и «Пример»**: обновить страницу — значения формы
   восстанавливаются; кнопка «Пример: Алматы» заполняет форму, но цифры
   приходят только из API (проверяется после мержа frontend-ветки).
5. **Оффлайн**: DevTools → Network → Offline → «Рассчитать» — русская ошибка
   с подсказкой; снять Offline → повтор — работает.

## Ограничения модели

- `Kc` — только mid-season; стадия роста и сезон не моделируются.
- Дизель считается для одного прохода техники.
- Тип почвы, поливочная техника и потери при поливе не учитываются.
- Это оценка для планирования, а не точный агрономический прогноз.
